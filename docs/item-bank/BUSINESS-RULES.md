# item-bank-php 비즈니스 규칙 후보

> 모듈 구조는 [ARCHITECTURE.md](./ARCHITECTURE.md), 테이블 · 뷰는 [ERD.md](./ERD.md) 를 봅니다.
> 경로는 따로 표시하지 않으면 `legacy/item-bank-php/` 기준입니다. `schema.sql` 은 `db/mariadb/init/01-schema.sql` 입니다.

## 조사 범위

- 읽은 파일: `search.php`(전체), `register.php`(전체), `units.php`(전체), `inc/db.php`, `db/mariadb/init/01-schema.sql` 의 `item` · `tag` 정의와 `v_item_public` 뷰(`:20-70`)
- 규칙은 코드의 조건문 · SQL 에서 확인한 것만 적었습니다. 컨테이너를 띄워 실제 응답으로 확인하지는 않았습니다.
- **문항 수정 기능은 이 모듈에 없습니다.** `UPDATE` 문이 없고(ERD.md 3절), 쓰기는 `register.php` 의 INSERT 뿐입니다. 그래서 "등록 · 수정 시의 검증"은 등록 검증만 적었습니다.
- 확신도: **확실** = 조건문 · SQL 로 확인 / **추정** = 이름이나 주석으로 짐작

## A. 문항 검색 — 대상과 조건 조합 (`search.php`)

### BR-01 공개 문항만 검색한다
- 규칙: 문항의 `status` 가 `'A'` 이면 검색 대상에 넣고, 그 밖의 상태면 넣지 않는다.
- 근거: `search.php:522`, `search.php:526`, `schema.sql:70`
- 근거 코드:
  ```php
  $from   = " FROM v_item_public";                     // search.php:522
  ```
  ```sql
  WHERE i.status = 'A';                                 -- schema.sql:70
  ```
- 확신도: 확실
- 비고: 건수(`count_sql`)와 목록(`sql`)이 같은 뷰 · 같은 WHERE 를 씁니다(`:525-526`). 뷰 주석(`schema.sql:51`)은 "검색 화면 search.php 와 등록 화면이 모두 이 뷰를 기준으로 삼는다"고 하지만 `register.php` 는 이 뷰를 쓰지 않습니다(주석과 코드 불일치).

### BR-02 검색 조건은 모두 AND 로 결합한다
- 규칙: 키워드 · 단원 · 난이도 · 태그가 여러 개 주어지면 모든 조건을 동시에 만족하는 문항만 돌려준다.
- 근거: `search.php:44`, `:98`, `:118`, `:215`, `:218`, `:244`
- 근거 코드:
  ```php
  $where    = " WHERE 1=1";
  $where .= " AND unit_code = ?";
  $where .= " AND EXISTS (SELECT 1 FROM item_tag it JOIN tag t ON t.id = it.tag_id"
  ```
- 확신도: 확실
- 비고: OR 결합 경로는 없습니다. 키워드 안의 `title` / `stem` 만 OR 입니다(BR-04).

### BR-03 파라미터가 배열로 오면 첫 값만 쓴다
- 규칙: `q` · `unit` · `level` · `tag` · `sort` · `dir` · `page` 가 배열(`?tag[]=a&tag[]=b`)이면 첫 번째 값만 조건으로 쓴다.
- 근거: `search.php:55`, `:59`, `:63`, `:67`, `:71`, `:75`, `:79`
- 근거 코드:
  ```php
  $tag = is_array($params['tag']) ? (string)reset($params['tag']) : (string)$params['tag'];
  ```
- 확신도: 확실
- 비고: 태그 · 단원 · 난이도는 다중 선택이 불가능합니다.

### BR-04 키워드는 제목 또는 지문의 부분 일치로 찾는다
- 규칙: 키워드(`q`)를 앞뒤 공백 제거한 뒤 비어 있지 않으면 `title` 또는 `stem` 에 그 문자열이 포함된 문항만 돌려준다.
- 근거: `search.php:85`, `:90`, `:97-98`
- 근거 코드:
  ```php
  $like = '%' . $q . '%';
  $where .= " AND (title LIKE ? OR stem LIKE ?)";
  ```
- 확신도: 확실
- 비고: 대소문자 구분 여부는 DB 콜레이션에 달려 있어 코드로는 확인되지 않습니다.

### BR-05 키워드가 100자를 넘으면 100자로 자르고 경고한다
- 규칙: 공백 제거 후 키워드가 100자(UTF-8 문자 수)를 넘으면 앞 100자만 쓰고 경고를 표시한다.
- 근거: `search.php:86-88`, `:494`
- 근거 코드:
  ```php
  if (mb_strlen($q, 'UTF-8') > 100) {
      $q = mb_substr($q, 0, 100, 'UTF-8');
  ```
- 확신도: 확실
- 비고: 매직 넘버 100. 입력창에도 `maxlength="100"` 이 따로 적혀 있습니다(`:494`) — 같은 값이 두 곳에.

### BR-06 키워드의 `%` · `_` 는 이스케이프하지 않고 와일드카드로 쓴다
- 규칙: 키워드에 `%` 나 `_` 가 있으면 경고만 표시하고, 그 문자를 LIKE 와일드카드로 그대로 적용한다.
- 근거: `search.php:94-95`, `:97`
- 근거 코드:
  ```php
  if (strpos($q, '%') !== false || strpos($q, '_') !== false) {
      $warnings[] = '키워드의 % 와 _ 는 와일드카드로 처리됩니다.';
  ```
- 확신도: 확실
- 비고: 예) `q=_` 이면 1자 이상인 제목 · 지문이 모두 일치합니다.

### BR-07 한 글자 키워드는 허용하되 경고한다
- 규칙: 키워드가 정확히 1자이면 검색은 그대로 하고 "결과가 많을 수 있다"는 경고를 표시한다.
- 근거: `search.php:91-92`
- 근거 코드:
  ```php
  if (mb_strlen($q, 'UTF-8') === 1) {
      $warnings[] = '키워드가 한 글자라 결과가 많을 수 있습니다.';
  ```
- 확신도: 확실
- 비고: 최소 길이 제한은 없습니다.

### BR-08 단원은 단원 코드와 정확히 일치하는 문항만 찾는다
- 규칙: 단원(`unit`)을 앞뒤 공백 제거한 뒤 비어 있지 않으면 `unit_code` 가 그 값과 같은 문항만 돌려준다.
- 근거: `search.php:109-110`, `:118-120`
- 근거 코드:
  ```php
  $where .= " AND unit_code = ?";
  $values[] = $unit;
  ```
- 확신도: 확실
- 비고: 검색은 단원 **코드**, 등록은 단원 **id** 로 지정합니다(BR-27) — 같은 "단원" 입력이 화면마다 다른 키를 씁니다.

### BR-09 단원 코드 형식 · 대소문자 · 존재 여부가 틀려도 막지 않고 경고만 한다
- 규칙: 단원 코드가 `영문1자 + 숫자1~2자리 + '-' + 숫자1~2자리` 형식이 아니거나, 소문자를 포함하거나, `unit` 테이블에 없으면 경고를 표시하고 입력값 그대로 조회한다.
- 근거: `search.php:111-113`, `:115-116`, `:125`, `:141-142`
- 근거 코드:
  ```php
  if (!preg_match('/^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$/', $unit)) {
  if ($unit !== strtoupper($unit)) {
      $warnings[] = '단원 코드는 대문자로 입력하세요. (입력값 그대로 조회합니다)';
  ```
- 확신도: 확실
- 비고: 대문자로 바꾸지 않고 조회하므로, `m5-1` 이 `M5-1` 과 일치하는지는 DB 콜레이션에 달려 있습니다(코드로 미확인). 주석 `:112` "결과는 대개 0건" 은 결과가 아니라 기대이며 코드가 보장하지 않습니다.

### BR-10 난이도를 비우면 난이도 5 문항을 제외한다
- 규칙: 난이도(`level`)가 비어 있으면 `level < 5` 조건을 붙여 난이도 1~4 문항만 돌려준다.
- 근거: `search.php:211`, `:213-215`
- 근거 코드:
  ```php
  // 난이도 값이 비어 있으면 전체 난이도 검색 (1~5 모두 포함)
  if ($level == '') {
      $where .= " AND level < 5";
  ```
- 확신도: 확실
- 비고: **주석과 코드 불일치.** 주석 `:213` 과 파일 머리 주석 `:8`("1~5, 빈값 허용"), 선택 목록 라벨 "전체"(`:192`)는 모두 1~5 전체를 뜻하지만, 코드는 5를 뺍니다. 조건 없이 검색해도 난이도 5 문항은 나오지 않고, 난이도 5 문항은 `level=5` 로 지정할 때만 보입니다. 기본 정렬이 "어려운 문항부터"(BR-16)인데 최상 난이도가 기본 결과에서 빠지는 점도 어긋납니다. 의도인지 버그인지는 코드로 판단할 수 없습니다. 매직 넘버 5.

### BR-11 난이도가 1~5 한 자리 숫자이면 그 값과 같은 문항만 찾는다
- 규칙: 공백 제거한 난이도가 정규식 `^[1-5]$` 에 맞으면 `level = 값` 인 문항만 돌려준다.
- 근거: `search.php:217-220`
- 근거 코드:
  ```php
  else if (preg_match('/^[1-5]$/', $level)) {
      $where .= " AND level = ?";
      $values[] = (int)$level;
  ```
- 확신도: 확실
- 비고: 범위(이상 · 이하) 검색은 없습니다.

### BR-12 난이도가 1~5 형식이 아니면 경고하고 정수로 바꿔 그대로 비교한다
- 규칙: 난이도가 비어 있지 않고 `^[1-5]$` 에 맞지 않으면 경고를 표시하고, PHP `(int)` 변환 값과 같은 `level` 을 찾는다.
- 근거: `search.php:223-228`
- 근거 코드:
  ```php
  $warnings[] = '난이도는 1~5 사이여야 합니다.';
  $where .= " AND level = ?";
  $values[] = (int)$level;
  ```
- 확신도: 확실
- 비고: 주석 `:224` 은 "대개 0건" 이라고 하지만, `(int)` 변환 때문에 `03` · `3.7` · `3abc` 는 모두 3 이 되어 **난이도 3 문항이 경고와 함께 조회됩니다**. `abc` 는 0 이 되어 0건입니다. 등록 화면은 같은 입력을 오류로 거부합니다(BR-28) — 같은 "1~5" 규칙이 두 곳에서 다르게 동작합니다.

### BR-13 태그는 태그 이름과 정확히 일치하는 문항만 찾는다
- 규칙: 태그(`tag`)를 앞뒤 공백 제거한 뒤 비어 있지 않으면, 그 이름의 태그가 연결된 문항만 돌려준다.
- 근거: `search.php:235-236`, `:244-247`
- 근거 코드:
  ```php
  $where .= " AND EXISTS (SELECT 1 FROM item_tag it JOIN tag t ON t.id = it.tag_id"
          . " WHERE it.item_id = v_item_public.id AND t.name = ?)";
  ```
- 확신도: 확실
- 비고: 태그는 1개만 지정할 수 있습니다(BR-03). 문항에 다른 태그가 더 붙어 있어도 일치하는 태그가 하나 있으면 결과에 들어갑니다.

### BR-14 태그의 `%` · `_` 는 부분 일치로 쓰지 않는다
- 규칙: 태그에 `%` 나 `_` 가 있으면 "부분 일치를 지원하지 않는다"고 경고하고, 문자 그대로 `=` 비교한다.
- 근거: `search.php:237-238`, `:245`
- 근거 코드:
  ```php
  if (strpos($tag, '%') !== false || strpos($tag, '_') !== false) {
      $warnings[] = '태그는 부분 일치를 지원하지 않습니다.';
  ```
- 확신도: 확실
- 비고: 키워드(BR-06)는 `%` · `_` 를 와일드카드로 쓰고 태그는 쓰지 않습니다 — 같은 문자에 대한 처리가 조건마다 반대입니다.

### BR-15 태그가 50자를 넘거나 등록되지 않은 이름이면 경고만 하고 조회한다
- 규칙: 태그가 50자를 넘으면 앞 50자로 자르고 경고하며, `tag` 테이블에 없는 이름이면 경고를 표시하고 그대로 조회한다.
- 근거: `search.php:240-242`, `:251-259`
- 근거 코드:
  ```php
  if (mb_strlen($tag, 'UTF-8') > 50) {
      $tag = mb_substr($tag, 0, 50, 'UTF-8');
  ```
- 확신도: 확실
- 비고: 매직 넘버 50 은 `tag.name VARCHAR(50)`(`schema.sql:37`)과 같은 값입니다. 등록 여부는 DB 재조회가 아니라 폼 선택 목록(`$tagOptions`, `:178`)과 비교합니다. 주석 `:250` "→ 0건" 은 기대이며 코드가 보장하지 않습니다.

## B. 문항 검색 — 정렬 · 페이지 (`search.php`)

### BR-16 정렬 기준이 없으면 난이도 내림차순, 같으면 ID 오름차순으로 정렬한다

- 근거: `search.php:317-319`

- 확신도: 확실

### BR-17 알 수 없는 정렬 기준이면 경고하고 기본 정렬을 쓴다
- 규칙: `sort` 가 `id` · `title` · `unit` · `level` · `created`(대소문자 무시, 공백 제거) 가 아니면 경고를 표시하고 BR-16 정렬을 쓴다.

- 비고: 기본 정렬 SQL 문자열이 `:319` 와 `:325` 두 곳에 중복돼 있습니다.

### BR-18 정렬 방향이 asc · desc 가 아니면 경고하고 기준별 기본 방향을 쓴다
- 규칙: `dir` 이 `asc` · `desc`(대소문자 무시)가 아니면 비어 있지 않을 때만 경고하고, 방향 미지정으로 처리한다.

- 확신도: 확실
- 비고: 방향 미지정 시 기본 방향은 BR-19 를 봅니다.

### BR-19 방향을 지정하지 않으면 `level` · `created` 는 내림차순, 나머지는 오름차순이다

- 확신도: 확실
- 비고: SQL 분기(`:278-314`)와 화면 표시용 방향(`:330`)이 따로 구현돼 있지만 결과는 같습니다. 열 머리글 링크도 난이도만 첫 클릭이 내림차순입니다(`:410-412`).

### BR-20 정렬 동률은 항상 ID 오름차순으로 가린다
- 규칙: `title` · `unit` · `level` · `created` 정렬에서 값이 같으면, 정렬 방향과 관계없이 `id ASC` 로 순서를 정한다.

- 비고: 내림차순이어도 2차 키는 오름차순입니다.

### BR-21 단원 정렬은 방향과 관계없이 같은 단원 안에서 난이도 내림차순이다
- 규칙: `sort=unit` 이면 `unit_code` 를 지정 방향으로 정렬하고, 같은 단원 안에서는 항상 `level DESC, id ASC` 로 정렬한다.
- 근거: `search.php:295`, `:297`
- 근거 코드:

### BR-23 페이지 번호는 1~999 로 보정한다

## C. 문항 등록 검증 (`register.php`)

### BR-25 제목은 앞뒤 공백을 뺀 5자 이상 200자 이하여야 한다
- 규칙: 앞뒤 공백을 제거한 제목의 UTF-8 문자 수가 5 미만이거나 200 을 넘으면 등록을 거부한다.
- 근거: `register.php:41`, `:49-54`
- 근거 코드:
  ```php

  ```
- 확신도: 확실
- 비고: 주석 `:48` "공백 제외 아님, 앞뒤 공백만 제거" 와 코드 일치 — 가운데 공백도 글자 수에 들어갑니다(`"a b c"` = 5자 통과). 200 은 `item.title VARCHAR(200)`(`schema.sql:23`)과 같은 값. 제목 중복 검사는 없습니다. 매직 넘버 5 · 200.

### BR-26 지문은 앞뒤 공백을 뺀 뒤 비어 있으면 안 된다
- 규칙: 앞뒤 공백을 제거한 지문이 빈 문자열이면 등록을 거부한다.

### BR-27 단원은 존재하는 단원 id 여야 한다
- 규칙: `unit_id` 가 `unit` 테이블의 id 중 하나와 문자열로 같지 않으면 등록을 거부한다.

### BR-28 난이도는 1~5 한 자리 숫자여야 한다
- 규칙: 공백 제거한 난이도가 `^[1-5]$` 에 맞지 않으면 등록을 거부한다.

### BR-29 목록에 없는 태그 id 는 오류 없이 버린다
- 규칙: 선택한 태그 id 가운데 `tag` 테이블에 없는 것은 오류 메시지 없이 제외하고, 남은 태그만 연결한다. 태그는 0개여도 된다.

### BR-30 새 문항은 검수중(`R`)으로 저장한다
- 규칙: 검증을 통과하면 문항을 `status = 'R'` 로 저장하므로, 공개(`A`)로 바뀌기 전까지 검색(BR-01)과 단원별 문항 수(BR-32)에 나오지 않는다.
- 근거: `register.php:84`, `:93-94`, `:116`
- 근거 코드:
  ```php

  ```
- 확신도: 확실
- 비고: 컬럼 기본값은 `'A'`(`schema.sql:26`)지만 등록 코드는 `'R'` 을 명시합니다. `R` → `A` 로 바꾸는 코드는 이 모듈에 없습니다(ERD.md 4절).

### BR-31 새 문항 id 는 현재 최대 id + 1 이다
- 규칙: 문항을 등록할 때 트랜잭션 안에서 `MAX(id) + 1`(문항이 없으면 1)을 새 id 로 쓰고, 문항 · 태그 저장 중 하나라도 실패하면 모두 되돌린다.
- 근거: `register.php:85`, `:87`, `:114`, `:119-120`
- 근거 코드:
  ```php
  $res = $conn->query("SELECT COALESCE(MAX(id), 0) + 1 AS next_id FROM item FOR UPDATE");
  $conn->rollback();
  ```
- 확신도: 확실
- 비고: `item.id` 에 AUTO_INCREMENT 가 없어서 생긴 규칙입니다(ERD.md 1절). 삭제(`D`) 문항도 `item` 에 남아 있으므로 MAX 계산에 포함됩니다. `created_at` · `updated_at` 은 DB 서버 시각 `NOW()` 입니다.
