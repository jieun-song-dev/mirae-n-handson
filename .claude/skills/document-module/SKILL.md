# 레거시 모듈 문서화

- 분석 대상 폴더(`$ARGUMENTS` 의 모듈 경로)의 파일은 읽기만 한다. 수정 · 삭제 · 포맷팅하지 않는다.
- 문서는 한국어로 쓴다. 파일 쓰기는 `docs/<모듈명>/` 아래에만 한다.
- `<모듈명>` 은 폴더 이름이 아니라 아래 셋 중 하나다. 이 밖의 경로면 멈추고 사용자에게 모듈명을 묻는다.
  - `legacy/item-bank-php` → `item-bank` / `legacy/assignment-thymeleaf` → `assignment` / `legacy/grade-mssql` → `grade`
- 범위 제한 인자가 있으면 그 파일 · 기능만 보고, 문서의 "조사 범위"에 제한 내용을 적는다.

## 0. 계획 먼저 제시
- 파일 목록(Glob)과 크기만 보고 분석 계획을 보여 준다: 읽을 파일, 단계 1~4 에서 볼 것, 만들 산출물 3개.
- 사용자가 계획을 확인한 뒤 1단계로 넘어간다.

## 1. 진입점
- 사용자 요청이 처음 닿는 곳(페이지 · 컨트롤러 · 프로시저)과 URL · 파라미터를 표로 정리한다.
- `docs/<모듈명>/ARCHITECTURE.md` 에 "진입점" 절로 저장한 뒤 다음 단계로 넘어간다.

## 2. 의존 관계
- include · import · 호출 관계를 실제 호출문의 `파일:줄번호` 로 적는다. 호출하는 쪽 → 호출되는 쪽 방향으로 쓴다.
- 외부 자원(DB 접속, 공용 파일, 설정)을 함께 적는다.
- ARCHITECTURE.md 에 "의존 관계" 절을 추가 저장한 뒤 다음 단계로 넘어간다.

## 3. 데이터 흐름
- 입력 → 검증 → SQL(테이블 · 뷰) → 출력 순서로 기능별 흐름을 적는다.
- 테이블 · 뷰 · 컬럼 · 관계는 스키마 파일(`db/**/init/*.sql`, 프로시저 `sql/*.sql`)에서 확인해 `docs/<모듈명>/ERD.md` 에 저장한다(Mermaid `erDiagram` + 컬럼 표). 읽기 · 쓰기(INSERT/UPDATE/DELETE) 위치를 표시한다.
- ARCHITECTURE.md 에 "데이터 흐름" 절을 추가 저장한 뒤 다음 단계로 넘어간다.

## 4. 비즈니스 규칙 후보
- 조건문 · SQL · 상수에서 규칙을 뽑아 `docs/<모듈명>/BUSINESS-RULES.md` 에 아래 형식으로 저장한다.

```markdown
### BR-01 <규칙을 한 문장으로>
- 규칙: <조건과 결과를 동작으로 서술>
- 근거: `search.php:522`, `schema.sql:70`
- 근거 코드:
  ```php
  $from = " FROM v_item_public";   // search.php:522
  ```
- 확신도: 확실 | 추정
- 비고: <주석과 코드 불일치, 같은 규칙의 다른 구현, 예외 경로 등>
```

- 확신도: **확실** = 조건문 · SQL 로 확인 / **추정** = 이름 · 주석으로 짐작. 추정은 비고에 이유를 적는다.
- 문서 앞머리에 "조사 범위"(읽은 파일, 실행 확인 여부), 끝에 "매직 넘버", "주석만 있는 항목", "미확인" 절을 둔다.

## 5. 사람이 표본 점검할 규칙 3개 추천
- BUSINESS-RULES.md 끝에 "표본 점검 추천" 절을 두고 3개를 고른다. 사람이 원본 코드와 대조해 확인할 목적이다.
  - 가장 그럴듯한 규칙 1개(확실해 보여서 오히려 검증 없이 넘어가기 쉬운 것)
  - 추정이거나 주석과 코드가 어긋난 규칙 1개
  - 근거가 여러 파일에 걸친 규칙 1개
- 각각 규칙 ID, 고른 이유, 확인할 `파일:줄번호` 를 적는다.
- 마지막 답변에는 산출물 3개의 경로, 규칙 수(확실/추정), 표본 점검 추천 3개만 짧게 보고한다.

## 하지 말 것
- 코드에 없는 함수 · 파일 · 테이블 이름을 쓰지 않는다. 이름을 적기 전에 Grep 으로 정의가 있는지 확인하고, 없으면 "미확인"에 둔다.
- 호출 방향을 뒤집어 적지 않는다. "A 가 B 를 호출" 은 A 파일 안의 호출문 줄번호가 있을 때만 쓴다.
- 코드에 없는 규칙을 만들지 않는다. 일반적인 관행(권한 검사, 중복 방지, 소프트 삭제 등)이라도 조건문 · SQL 로 확인되지 않으면 규칙으로 올리지 않는다.
- 주석 · 변수 이름만 보고 "확실"로 적지 않는다. 주석과 코드가 다르면 코드를 규칙으로, 주석은 비고에 적는다.
- 줄번호를 기억으로 적지 않는다. 인용한 코드는 Read 로 그 줄을 다시 확인한 뒤 적는다.
- 한 단계의 결과를 파일로 저장하기 전에 다음 단계로 넘어가지 않는다.
