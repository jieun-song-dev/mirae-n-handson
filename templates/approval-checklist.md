# 승인 체크리스트 v1

> **v1 · 2회차** (2026-10-06)
> - 주관 표현 항목 4개(테스트가 충분하다 · 심각한 문제가 없다 · 지나치게 많지 않다 · 적절하게 맞는다)를 지우고 예/아니오 항목으로 바꿨다.
> - 테스트 기준을 "새 public 메서드마다 테스트 1개 이상(접근자 제외)"으로, 치명 이슈를 4종(비밀값 노출 · 데이터 손실 · 인증 우회 · SQL 문자열 조립)으로 정했다.
> - 범위 밖 변경은 같은 파일 안 import 정리만 허용하고, 컨벤션은 반려 3종(계층 · 빈 catch · System.out)과 경고(네이밍)로 나눴다.

AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 모든 항목은 "예"가 충족이다. 네 기준이 **모두** 충족되어야 승인이다. 하나라도 미충족이면 반려.

## 심각도 정의

- **치명** — §2 항목이 "아니오". 1건이라도 있으면 반려.
- **반려** — §1 · §3 항목 또는 §4 반려 항목(4-1~4-6)이 "아니오". 1건이라도 있으면 반려.
- **경고** — §4 경고 항목(4-7~4-9)이 "아니오". 판정에 영향 없음. 수정 요청에 포함한다.
- **제안** — 더 나은 방법이 있다는 의견. 승인 · 반려에 영향을 주지 않는다. 목록으로만 남긴다.

이슈 한 건은 심각도 · 항목 번호 · `파일:줄번호` · 근거 · 수정 방향 다섯 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 1. 테스트 통과

- [ ] 1-1 변경된 모듈의 테스트 명령을 실제로 실행했고, 실행 명령과 통과 · 실패 수를 기록했다(실행하지 않고 통과라고 쓰지 않는다).
- [ ] 1-2 실행 결과에 실패 · 오류가 0건이다.
- [ ] 1-3 diff 에서 새로 생긴 public 메서드마다 그 메서드를 호출하는 테스트가 1개 이상 있다(근거로 테스트의 `파일:줄번호`를 적는다).
  - 대상: Controller 엔드포인트 메서드를 포함한 모든 새 public 메서드
  - 제외: getter · setter · 생성자, record 의 컴포넌트 접근자, public 이 아닌 메서드
- [ ] 1-4 기존 테스트를 지우거나 건너뛰게(`skip`, `@Disabled`) 바꾼 곳이 없다.

## 2. 치명 이슈 0건

- [ ] 2-1 (비밀값 노출) 비밀번호 · 토큰 · 키 · 접속 계정이 코드 · 설정 · 테스트 픽스처에 리터럴로 들어 있지 않다(예외: 실습용 더미 `app-pass`).
- [ ] 2-2 (비밀값 노출) 로그 · 예외 메시지 · 응답 본문에 비밀번호 · 토큰 · 키 값을 넣는 곳이 없다.
- [ ] 2-3 (데이터 손실) 데이터를 지우거나 덮어쓰는 코드(`DELETE` · `UPDATE` · `deleteBy*` · `DROP` · `TRUNCATE`)가 새로 생기지 않았다. 생겼다면 요청 문장에 그 동작이 적혀 있다.
- [ ] 2-4 (인증 우회) 인증 · 권한 검사(필터 · 인터셉터 · 어노테이션 · 토큰 검증)를 지우거나 주석 처리하거나 조건부로 건너뛰게 바꾼 곳이 없다.
- [ ] 2-5 (SQL 문자열 조립) SQL · JPQL 에 값을 `+` · `String.format` · `concat` 으로 이어 붙이는 곳이 없다(파라미터 바인딩 사용).

## 3. 요청 범위 이탈 없음

- [ ] 3-1 요청 문장이 한 문장으로 확인되었다(없으면 판정하지 않고 먼저 묻는다).
- [ ] 3-2 변경 파일 목록의 모든 파일이 요청 문장으로 설명된다.
- [ ] 3-3 요청으로 설명되는 파일 안에서 요청과 무관하게 바뀐 줄은 import 정리(추가 · 삭제 · 순서)뿐이다.
- [ ] 3-4 의존성 추가 · DB 스키마 변경 · 설정 파일 변경이 없다. 있다면 요청 문장에 포함돼 있다.

## 4. 컨벤션 준수

- [ ] 4-0 팀 `CLAUDE.md` 의 코딩 컨벤션과 대조했다(`convention-check` Skill 이 있으면 그 결과를 쓴다).

반려 항목 — 하나라도 "아니오"면 미충족이다.

- [ ] 4-1 (계층) Controller 의 필드 · 생성자 인자에 `*Repository` · `EntityManager` · `JdbcTemplate` 타입이 없다.
- [ ] 4-2 (계층) Controller 메서드 본문은 Service 메서드 호출과 그 결과 반환만 한다.
- [ ] 4-3 (계층) Controller 메서드의 반환 타입이 `@Entity` 클래스가 아니다.
- [ ] 4-4 (계층) Service 가 다른 도메인 패키지의 `*Repository` 를 주입하지 않는다.
- [ ] 4-5 (빈 catch) 모든 `catch` 블록에 `log.warn`/`log.error` 호출 또는 `throw` 가 하나 이상 있다.
- [ ] 4-6 (System.out) `System.out` · `System.err` · `e.printStackTrace()` 호출이 없다.

경고 항목 — "아니오"여도 판정에 영향이 없다.

- [ ] 4-7 (네이밍) 클래스는 PascalCase, 메서드 · 필드는 camelCase, 상수는 UPPER_SNAKE_CASE 이고, 약어는 첫 글자만 대문자다.
- [ ] 4-8 (네이밍) 테스트 메서드 이름이 확인하는 동작을 camelCase 로 적는다.
- [ ] 4-9 (그 밖) 위에 없는 `CLAUDE.md` 컨벤션을 지킨다: 테스트 클래스의 `@ActiveProfiles("test")` · 한국어 `@DisplayName`, 0 · 1 · -1 이외 숫자 리터럴의 상수화, Service 의 `Clock` 주입, 로그에 `STU-` · 이메일 미포함, `console.log` 없음.

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족 표(근거 칸에 미충족 항목 번호), 그다음 이슈 목록(심각도 · 항목 번호 · `파일:줄번호` · 근거 · 수정 방향). 코드는 수정하지 않는다.
